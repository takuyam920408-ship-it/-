# 漫画紹介ショート台本

漫画作品の中身を短く紹介し、「続きが気になる」状態で概要欄の作品リンクへ送るショート動画の台本を作る。リンク先はX・Blueskyの投稿や電子書籍ストアで、アフィリエイト収益の入口になる。

型と数値は、登録者1万人以下で100万回再生級のショートを出している漫画紹介チャンネル49件（ベンチマーク元は「漫画ムラ【反応集】」）の自動字幕・尺・タイトル約4,200本・概要欄の分析から得たもの。制作の進め方（3体制レビュー・抜け漏れチェック・記録・2本立て納品）と言葉のルールは、ユーザーの反応集チャンネル「バズらないと【反応集】」の台本スキル（anime-daihon-hanoushuu）で積み上げたルールを取り入れている。

根拠を確かめたいときは `references/analysis.md`、初めて書くときや型に迷ったときは記入例 `references/examples.md` を読む。

## 制作の流れ

| 工程 | やること | 詳しく |
|---|---|---|
| ⓪ リサーチ | FANZAで最新の評価が高い漫画を探し、候補から選んだ作品のストーリー文を取り込む | 0章・`references/research.md` |
| ① 資料の確認 | 作品の資料・誘導先URL・型を確かめる | 1章 |
| ② 作成 | プレーン版の台本を書き、チェックスクリプトを通す | 2〜8章 |
| ③ 3体制レビュー | 伸ばす担当・信頼担当・構成担当に見せ、全員が「問題なし」になるまで直す | 9章・`references/review.md` |
| ④ 抜け漏れチェック | 予告と中身がつながっているかを自分で通し読みして確かめる | 10章・`references/review.md` |
| ⑤ 記録 | バズ分析5観点をバズ分析ノートに追記する | 11章・`references/review.md` |
| ⑥ 納品 | プレーン版とカット割り版の2ファイルを渡す | 12章・`references/cutwari.md` |

ユーザーが「レビューなしで」「急ぎで」と言ったときだけ③を省いてよい。その場合も④は省かない。

## 0. リサーチ（FANZAで作品を探す）

紹介する作品は、FANZAで**最新の評価が高い漫画**から選ぶ。手順の詳細は `references/research.md` にある。ユーザーが作品を指定してきた場合は飛ばして1章に進む。

1. FANZAの同人・電子書籍のコミックから、発売3か月以内・評価が高い（平均4.5以上かつレビュー10件以上が目安）作品を集める。ブラウザ操作ツール、DMMのアフィリエイトAPI、どちらも使えなければユーザーに作品ページと紹介文を貼ってもらう、の順で手段を選ぶ
2. 学生・子どもに見えるキャラが中心の作品、無理やりが中心の作品、性的な場面以外に展開がない作品、女性向け・BL・TLは除外する
3. **10作品**を表で見せて、ユーザーに選んでもらう。選ぶのはユーザーなので、返事が来るまで台本作りに進まない
4. ユーザーが選んだ作品の作品紹介文（ストーリー文）をそのまま資料として控え、1章に進む

## 1. 資料を確認する

台本は実在の作品の紹介なので、材料は0章で取り込んだストーリー文か、ユーザーから渡されたものを使う。

- **作品の資料**：作品名、ストーリー文（あらすじ）、登場人物（名前・年齢・関係）、見どころの場面。漫画のページ画像が渡されたら読んで使う
- **誘導先URL**：なければ概要欄は `https://x.gd/〇〇〇〇〇` のまま残し、差し替えが必要だと伝える
- **型の指定**：なければA型（ストーリー要約型・CTA締め）で書く

**資料にない展開・設定・結末を創作しない。** 反応集スキルの「ファクトチェック必須」を漫画紹介に置き換えたルールで、事実の基準はFANZAのストーリー文（またはユーザーから渡された資料）になる。ストーリー文の露骨な言葉は使わず匂わせに書き直し、概要欄にもそのまま貼らない（他人の文章のため、自分の言葉で書き直す）。視聴者は台本の続きを期待してリンクを開くので、紹介と中身がずれると離脱・低評価につながり、成約も落ちる。セリフは資料にある作中の言い回しを優先し、足す場合はその場面から自然に言える短い言葉にとどめ、足したことを納品時に伝える。材料が足りず350字に届かないときは、どこまで紹介してよいか・主要な場面などをユーザーに聞く。

**結末や核心は書かない。** クライマックスの一歩手前で止めることが、この形式の目的そのもの。

**誘導先URL**は、FANZAの作品ページURLをそのまま使わない。アフィリエイトIDの付いたリンク（またはそれを載せたX投稿・短縮URL）をユーザーに確認する。

## 2. 型を選ぶ

| | A. ストーリー要約型（標準） | B. 1コマ・5秒ループ型 |
|---|---|---|
| 使う場面 | 作品のあらすじを語れるとき | 1コマ・1ページで伝わる作品、「1コマ」「5秒」「タイトルだけ」と言われたとき |
| 尺 | 50〜57秒（60秒は超えない） | 5〜6秒 |
| 音声 | ナレーション＋セリフ＋ツッコミ | 読み上げなし、BGMのみ |
| 作るもの | タイトル・台本・サムネ文・ハッシュタグ・概要欄 | タイトル案3つ・画面と音のメモ・ハッシュタグ・概要欄 |

A型には締め方が2つある。指定がなければ「CTAで締める」を使う（24本中20本がこの形）。「漫画ムラっぽく」「ぶつ切りで」「ループさせたい」と言われたら「ぶつ切りで締める」にする。

## 3. A型の書き方

### 数値の目安

- 読み上げ文字数 **350〜420字**（話者ラベルは数えない）
- 話す速さは **1秒あたり約7字** の想定（普通より早口。伸びているチャンネルはほぼ7字以上）。これで尺が50〜60秒になる
- ツッコミ **2〜4回**

### 話者ラベル

VOICEVOXで声を分けるため、行の頭に話者ラベルを付ける（反応集のプレーン版はラベルなしだが、この形式は声を分けるのでラベルが必要）。

- `［ナレ］` 三人称の説明口調（「〜な主人公」「〜なのだ」）
- `［キャラ名］` 会話口調。キャラごとに声を分ける
- `［ツッコミ］` 2ch風の短い一言。反応集らしさを出す担当（ずんだもん等の軽い声を想定）

### 流れ

| 時間 | パート | 字数 | 書き方 |
|---|---|---|---|
| 0〜3秒 | ①フック［ナレ］ | 約20字 | タイトルをそのまま読み上げる。台本の中で一番強い一言をここに置く |
| 3〜5秒 | ②最初のセリフ［キャラ］ | 約15字 | 関係性が一発で分かる生のセリフ（告白・呼び出し・叱る・煽る） |
| 5〜20秒 | ③設定［ナレ］＋ツッコミ | 約100字 | 平凡な主人公 × 属性のはっきりしたヒロイン。最後は「そんなある日」「しかし」でつなぐ |
| 20〜45秒 | ④展開［ナレ＋キャラ］＋ツッコミ | 約170字 | 事件 → セリフのやり取り2〜4往復 → ナレでつなぐ。人物の意外な一面（本題）はここで出す |
| 45〜52秒 | ⑤クライマックス直前［ナレ］ | 約45字 | 核心の一歩手前で止める |
| 最後の3秒 | ⑥締め | 約20字 | CTA、またはぶつ切り（下記） |

**なぜ5秒以内にセリフか**：伸びている10チャンネル中7チャンネルが5秒以内にキャラの声を入れている。ナレーションだけが続くと「説明動画」に見えてスワイプされやすく、生のセリフで一気に物語の中に引き込むため。

**③設定は1文＝1情報**：名前・年齢・職業・肩書きを1文に詰め込まない。反応集の視聴維持率分析で、固有名詞や数字が並ぶ説明区間が最大の離脱ポイントだったため。「広告代理店で働く新人の佐伯」「彼の上司は 鉄壁と呼ばれる氷室課長」のように分ける。

**溜めを作る**：本題（人物の意外な一面）は、いきなり全部見せない。④で「何かある」と匂わせてから中身を見せる二段階にする。反応集で、核心の詳細を③まで温存する二段階開示が効いたのと同じ考え方。

**葛藤・危機・対立を1つ入れる**：「すごい」「かわいい」だけで終わらせず、秘密がバレる・条件を出される・ライバルが現れるなど、話が動く出来事を入れる。反応集の分析で、賞賛・感心だけで対立要素がないネタは伸びが弱かったため。

**ヒロインの属性**：「真面目・高嶺の花・強い・天才・完璧」など、意外な一面とのギャップが作れる人物を軸にする。何十倍も伸びた動画は、どれもタイトルだけで「属性 × 意外な行動」が分かるものだった。

**つなぎ言葉**：しかし／だが／そんなある日／ところが／こうして

**⑤の決まり文句**：彼女は予想外の行動に出る／その瞬間 彼女の様子が一変し／そこに書かれていたのは まさかの／ここから物語は〜な展開へ発展する

**⑥の締め方**
- CTAで締める［ナレ］：「この続きは概要欄をチェックして」「続きは画面を長押しして説明をタップでチェックして」
- ぶつ切りで締める（漫画ムラ型）：⑤の途中、または「結果決まってて草」などのツッコミで切り、頭に戻ってループさせる。導線は概要欄だけに任せる
- 「コメントで教えて」は使わない（反応集の検証で、直接コメントを求める言い方は逆効果だったため）

### ツッコミの語彙

設定の直後と展開の山場の直後に入れる。1回8字前後。視聴者の心の声として、「〜している」のような報告調ではなく口語で書く。
- 〜草（負け惜しみ草／結果決まってて草）
- 〜やな（贅沢な悩みやな）
- そらそうよ
- 〜じゃねえか（大発明じゃねえか）
- 〜だな（人生楽しいな／もはやホラーだな）

作品に合わせて同じ系統の言葉を作ってよい。

### 文章の書き方

- 読点（、）はなるべく使わず、区切りは改行か半角スペースで表す（読み上げが途切れずに進む）
- 英語は避け、日本語・カタカナにする（作品名や定着した言葉はそのまま）

## 4. タイトル

A型は、①のフックとタイトルを同じ文言にするのが基本（中央値14字）。

- 〔属性キャラ〕の〔秘密・裏の顔〕がヤバすぎた
- 〔行動〕したら最高すぎた
- 〔状況〕した結果
- 【悲報】〔属性キャラ〕が〜されてしまう…
- 漫画ムラ型：読み上げは2ch風スレタイ（「〜なワイが〜な理由がこちら」「〜なワイ 〜してしまう」）、タイトルはさらに短い一言（「彼女と別れられないワイ」「ただの勝ち組」「ハズレだと思ったら…」）

「ヤバすぎた」「最高すぎた」などの言葉を替えても再生数の差は±1割程度しかない。言葉選びより「属性 × 意外な行動」のギャップが一目で伝わるかを優先する。反応集のパラドックス構造（ポジティブとネガティブを1文に同居させる）と同じで、「鉄壁の上司」×「可愛すぎた」のように反対の要素をぶつけると強い。強い言葉を使うときは、それに見合う中身が台本にあるかを確かめる（釣りタイトルにしない）。

## 5. サムネ文（A型）

反応集と同じく、サムネイル下部に載せる5〜10字の一言を1つ添える。

- ④展開の核心（人物の意外な一面が出るセリフや、そこへのツッコミ）から切り出す。③設定の周辺情報から取らない（反応集で、核心を予告できていないサムネ文がフックにならなかった実例があるため）
- 状況説明の体言止めより、セリフ調を優先する（例：「誰か褒めて…」「鉄壁どこいった」）

## 6. B型の書き方

- 尺5〜6秒、読み上げなし、BGMのみ。1コマ（または1ページ）を見せ、画面の一言テロップ＝タイトルで状況を伝える
- 短いので何度もループされ、再生数が伸びやすい。最後の画面から最初に戻っても違和感がないようにする
- タイトル案は次の型から3つ出す（それぞれ20字以内が目安）

| 型 | 例 |
|---|---|
| ツッコミ・感想型 | 態度と好感度バグってる／色変わりすぎ／どういうこと？ |
| 見返させる謎かけ型 | これは下でしょ／理由はヒミツ／持ち物変わってる＝交わった？ |
| 属性＋一言型 | 警官の本性／太らせて食べるタイプ／男は顔だけじゃない |
| シリーズ型 | 人気漫画のアニメと実写化比較！② |

謎かけ型は、見返さないと答えが分からないのでループが生まれやすい。

## 7. 概要欄（A型・B型共通）

```
〔誘導先URL〕

↑URLを長押ししてリンクを開く
（iPhoneはダブルタップ）
※長押しで選択できない場合は スクショした画面からURLを長押し

【作品紹介】
〔あらすじ1〜3行。結末は伏せ「〜とは…？」「〜が気になる作品です」で締める〕

※アフィリエイト広告を利用しています
```

- URLは必ず1行目。スマホで概要欄を開いたとき最初に見える位置だから
- YouTubeアプリ内ではリンクが開けないことが多いので、開き方を毎回書く
- アフィリエイトリンクを使うときは最後の一文を入れる（ステマ規制の対策。アフィリエイトでない場合は外してよい）

## 8. 言い換えと守ること

反応集スキルの禁止ワードのルールをそのまま使う。
- 「エロ」→「江戸」、「えっち」→「ムホホ」
- 酷評系の言葉・表現は使わない
- 3P系の言葉・表現は使わない
- そのほかの直接的な言葉も伏せ字・隠語にする（競合では「メロン」「マシュマロ」「〇〇」「シたら」なども使われている）

漫画紹介で追加して守ること。
- 性的な含みは「匂わせ」までにとどめ、具体的な描写はしない
- **学生や子どもに見えるキャラを性的に匂わせる台本は書かない。** 性的な含みのある作品を扱うのは、登場人物が成人（大学生・社会人など）だと資料から明らかな場合に限る。学生キャラの作品で性的な展開しかない場合は、その作品は断るか、性的でない見どころを軸にする。YouTubeの規約違反でチャンネル停止に直結するうえ、そもそも書くべきでない内容のため

## 9. 3体制レビュー

プレーン版とカット割り版を書き、`scripts/check_script.py` で「要修正」がなくなったら、3人のレビュアーに見せる。手順・依頼文のひな形・担当ごとのチェック項目は `references/review.md` にある。

- **伸ばす担当**：最後まで見られるか、概要欄を開きたくなるか（フック・溜め・葛藤・止めどころ・サムネ文）
- **信頼担当**：資料との一致と規約（創作・誇張・釣りタイトル・ネタバレ・URL・未成年・禁止ワード・広告表記）
- **構成担当**：型と数値（流れの順番・文字数・セリフ位置・ツッコミ回数・話者ラベル・サムネ文・カット割り版との一致）

Agentツールがあれば3人を同時に起動する。直したら3人全員にもう一度見せ、全員が「問題なし」と言うまでラウンドを重ねる。ユーザーから渡された資料は毎回そのまま渡し、レビュアーごとに前提がずれないようにする。担当同士の指摘がぶつかって2往復したら、両方の意見を並べてユーザーに判断を聞く。

## 10. 抜け漏れチェック

3人全員が「問題なし」になったら、自分で台本を最初から最後まで通して読む。3人はそれぞれ専門に分かれているため、「予告したことと中身がつながっているか」は誰の担当にもならず抜けやすい。確認項目は `references/review.md` の④にある（予告したギャップが描かれているか、出しっぱなしの設定がないか、概要欄・サムネ文・ハッシュタグとのずれ、2ファイルの一致、守ることへの違反）。

## 11. 記録

確定した台本ごとに、バズ分析5観点（数字の落差・常識の反転・テーマの交差点・自分ごと化・行動への直結）で構成の狙いを短く書き、作業フォルダの「バズ分析ノート.txt」に日付付きで追記する。反応集と同じファイルなら先頭に【漫画紹介】と付ける。書式は `references/review.md` の⑤にある。

## 12. 納品

反応集と同じく、**プレーン版とカット割り版の2ファイルをセットで**渡す。どちらも `.txt`（`.md` だと単一改行が詰まって崩れるため）。保存先はユーザーの作業フォルダ（このリポジトリなら `クロコ台本作成とリサーチ/`）。

- プレーン版：`〔作品名〕_漫画紹介台本.txt`
- カット割り版：`〔作品名〕_漫画紹介台本_編集カット割り.txt`（作り方は `references/cutwari.md`）

チャットでは、2ファイルの場所と、レビューで直した主な点、ユーザーに確認してほしい点（資料にないセリフを足した箇所、URLの差し替え、固定フッターの中身など）を短く伝える。

### プレーン版の形式

構成ラベル（①フック等）や注記は台本に入れない。話者ラベルだけを付ける。

A型：

```
【型】A（ストーリー要約型／CTA締め）
【タイトル】
〔タイトル〕
【台本】
［ナレ］
〔①フック＝タイトル〕
［〔キャラ名〕］
```

## 13. 反応集ルールのうち、取り入れないもの

次の反応集ルールは、漫画紹介のベンチマークデータと合わないので使わない。反応集スキルと混ざらないように注意する。

| 反応集のルール | 漫画紹介では | 理由 |
|---|---|---|
| 尺は25〜33秒、40秒超は短縮 | 50〜57秒 | あらすじを語り切る必要があり、伸びている競合の中央値が53秒 |
| 冒頭文は「〜が話題に」で締める／【速報】＋作品名 | タイトルをそのまま読み上げる | 話題の紹介ではなく物語の紹介のため |
| 締めは行動を求めない断定・共感型 | 「続きは概要欄」のCTA、またはぶつ切り | 概要欄のリンクが収益の入口のため |
| 反応コメントを3つまとめて並べる | ツッコミを2〜4回、ナレの合間に散らす | 物語のテンポを止めないため |
| ネタ探しはX・5chのトレンドから | FANZAの最新・高評価の作品から探す（0章） | 話題ではなく作品そのものを紹介し、作品ページへ誘導する形式のため |
