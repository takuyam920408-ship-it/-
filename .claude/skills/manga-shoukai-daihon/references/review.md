# 3体制レビュー・抜け漏れチェック・記録

「バズらないと【反応集】」の台本スキル（anime-daihon-hanoushuu）8章の③〜⑤を、漫画紹介ショート向けに置き換えたもの。1人のAIの思い込みだけで納品しないための工程。

---

## ③ 3体制レビュー

台本（プレーン版・カット割り版）を書き上げたら、視点の違う3人のレビュアーに見せる。Agentツールが使える環境では、3人をサブエージェントとして**同時に**起動する。使えない環境では、自分で1人ずつ視点を切り替えて順番にレビューする（「いまは信頼担当として読む」と宣言してから読む）。

### 進め方

1. 下の「依頼文のひな形」に、ユーザーから渡された作品資料・台本・担当ごとのチェック項目を埋めて3人に渡す
2. 返ってきた指摘を踏まえて台本を直す
3. 直した台本を**3人全員にもう一度見せる**。全員が「問題なし」と言うまでラウンドを重ねる（1ラウンドで終わらせない）
4. 担当同士の指摘がぶつかって往復する場合（例：伸ばす担当は強い言葉を求め、信頼担当は誇張だと言う）は、2往復したところで両方の意見を並べてユーザーに判断を聞く
5. こちらで確認済みの資料（ユーザーが渡したあらすじ・ページ画像の内容）は毎回そのまま渡す。レビュアーごとに前提がずれて、同じ確認を繰り返さないようにするため

### 依頼文のひな形

```
あなたは漫画紹介ショート台本の【〔担当名〕】レビュアーです。
下の台本を、担当のチェック項目に沿ってレビューしてください。
台本は書き直さず、指摘と修正案だけを返してください。
型や数値の詳しい基準は /〔スキルのフォルダ〕/SKILL.md にあります。

■ 作品の資料（ユーザー提供。これが事実の基準）
〔あらすじ・登場人物・場面の説明・ページ画像の内容など〕

■ 台本（プレーン版）
〔全文〕

■ カット割り版（構成担当のときだけ）
〔全文〕

■ 担当のチェック項目
〔下の担当別リストを貼る〕

■ 返答の形式
判定：問題なし／要修正
指摘（要修正のときだけ。重要な順に）：
1. 該当箇所：「〜」
   問題：〜
   修正案：〜
```

### 伸ばす担当（最後まで見られて、概要欄を開きたくなるか）

- タイトル＝冒頭フックだけで「属性 × 意外な一面」のギャップが伝わるか。ポジティブとネガティブが1文に同居していると強い（例：鉄壁の上司の裏の顔が可愛すぎた）
- 冒頭3秒のフックと5秒以内のセリフで、スワイプする指を止められるか
- ③設定パートが説明だらけになっていないか。1文に固有名詞や数字を詰め込みすぎていないか（反応集の視聴維持率分析で、固有名詞・数字が並ぶ説明区間が最大の離脱ポイントだった）
- 溜めができているか。本題（人物の意外な一面）の詳細を早く出しすぎていないか。「何かある」と匂わせてから中身を見せる二段階になっているか
- ツッコミが視聴者の心の声になっていて、テンポを作っているか。説明的な文になっていないか（「〜している」の報告調ではなく「〜て草」「〜やろ」などの口語）
- 葛藤・危機・対立が1つ以上あるか。「すごい」「かわいい」だけで終わっていないか（反応集の分析で、賞賛だけのネタは伸びが弱かった）
- ⑤の止めどころが一番気になる瞬間になっているか。概要欄を開く動機として十分か
- サムネ文が、思わずタップしたくなる一言になっているか

### 信頼担当（作品資料との一致と、規約）

- 資料にない展開・設定・結末を足していないか。人物の名前・年齢・関係・職業が資料と一致しているか
- 資料にないセリフを足している場合、その場面から自然に言える範囲の短い言葉か。作中の決めゼリフのように見せていないか。作中のセリフが資料にあるなら、そちらを使っているか
- タイトル・フックの強い言葉（ヤバすぎた・最高すぎた・可愛すぎた等）に見合う中身が台本にあるか。釣りタイトルになっていないか（リンク先で期待と違うと、離脱・低評価・成約減につながる）
- 概要欄の作品紹介が台本・資料と矛盾していないか。結末や核心をばらしていないか
- 概要欄の誘導先URLが、ユーザーの指定どおりか
- 性的な含みは匂わせまでにとどまっているか。学生・子どもに見えるキャラを性的に扱っていないか。性的な含みがある場合、登場人物が成人だと資料から明らかか
- 禁止ワードと言い換え（エロ→江戸、えっち→ムホホ、酷評系・3P系の表現は使わない）を守っているか
- アフィリエイトリンクの場合、概要欄に「※アフィリエイト広告を利用しています」があるか

### 構成担当（型と数値）

- 型（A／B）と締め方（CTA／ぶつ切り）が依頼どおりか
- `scripts/check_script.py` の結果に「要修正」がないか（読み上げ350〜420字、最初のセリフ5秒以内、ツッコミ2〜4回、締め、概要欄の1行目がURL、開き方の案内、サムネ文の長さ）
- ①フック → ②最初のセリフ → ③設定 → ④展開 → ⑤クライマックス直前 → ⑥締め の順になっているか
- 話者ラベル（［ナレ］［キャラ名］［ツッコミ］）が正しく付いているか。ナレは三人称の説明口調、セリフは会話口調、ツッコミは短い口語になっているか
- 読点（、）を使わず改行か半角スペースで区切っているか。英語を使っていないか
- サムネ文が5〜10字で、④展開の核心（意外な一面が出るセリフやツッコミ）から切り出されているか。③設定の周辺情報から取っていないか
- カット割り版がプレーン版と文言・順番とも一致しているか。カットの秒数の合計がプレーン版の推定尺と±3秒以内か。1カットに情報が1つか

## ④ 抜け漏れチェック（3人全員が「問題なし」になったあとに、必ず自分で行う）

3人の担当はそれぞれ専門に分かれているため、「冒頭で予告したことと中身がつながっているか」という横断的な確認は誰の担当にもならず、抜け落ちやすい（反応集で、3ラウンドのレビューを通ってもタイトルと本文のずれが残り、ユーザーの指摘で発覚した実例がある）。台本を最初から最後まで通して読み、次を1つずつ照らし合わせる。

- タイトル・フックで予告したギャップ（意外な一面）が、台本の中で実際に描かれているか。予告だけして中身がない「言いっぱなし」になっていないか
- 冒頭〜③で出した人物・設定・小道具が、⑤までにどこかで使われているか。出しっぱなしのものがないか（⑤の核心そのものは止めてよい）
- 概要欄の作品紹介・サムネ文・ハッシュタグが、台本の中身とずれていないか
- プレーン版とカット割り版の文言が一致しているか
- SKILL.md の「守ること」（創作しない・結末を書かない・未成年を性的に扱わない・禁止ワード）に違反していないか

抜けが見つかったら直す。事実・型・伸びに関わる直しなら③に戻して3人に再確認する。言い回しやつなぎ程度の軽い直しなら、そのまま確定してよい。

## ⑤ 記録（バズ分析5観点）

確定した台本ごとに、なぜこの構成にしたかを5つの観点で短く書き、作業フォルダの「バズ分析ノート.txt」に日付付きで追記する（ファイルがなければ作る）。反応集の記録と同じファイルに入れる場合は、先頭に【漫画紹介】と付けて区別する。

```
【漫画紹介】YYYY-MM-DD 〔作品名〕／〔タイトル〕
型：A（CTA締め）
数字の落差：〔例　IQ200の天才少女／7年越しの片思い。なければ「なし」〕
常識の反転：〔例　鉄壁の鬼上司が 夜は褒められたがり〕
テーマの交差点：〔例　仕事 × 恋愛〕
自分ごと化：〔例　上司に毎日怒られる新人なら誰でも重ねられる〕
行動への直結：〔例　「今日は褒めるだけじゃ足りない」で止め 続きを見に概要欄を開く動機を作った〕
```
