# 答え合わせ速報の動画づくり

## このスキルについて

台本スキル（geinou-beforeafter-daihon）で確定した台本2ファイルを受け取り、投稿できる完成版の動画（声・効果音入り）とサムネを作る。反応集（remotion-hannoushuu・hannoushuu-gazou）と同じく、画像集めから書き出しまで自動で進め、**予約投稿の前にだけユーザーの承認をもらう**。

使うもの（リポジトリ `takuyam920408-ship-it/-` のブランチ `claude/serene-ramanujan-bampcq`、フォルダ `新チャンネル（芸能ビフォーアフター）/`）：
- `remotion-kotaeawase/`：動画のテンプレート（Remotion）。画面の決まりは全部ここに入っている。使い方は同じフォルダの README.md
- `remotion-kotaeawase/scripts/`：画像・スクショ・声・効果音・チェックのスクリプト（このスキルの `scripts/` にも同じものを入れてある。テンプレートにあればそちらを使う）
- 台本2ファイル：`〇〇_台本.txt`（タイトル・概要欄・タグ）と `〇〇_台本_編集カット割り.txt`（カットごとの写真・テロップ・写真リスト）
- ルール：`スキル/geinou-beforeafter-daihon/references/policy.md`（写真の権利）と `edit-design.md`（画面）

できあがり：`remotion-kotaeawase/out/<id>_kansei.mp4`（完成版）と `out/<id>_thumbnail.png`（サムネ）。芸能人の写真と完成版は**リポジトリに入れない**（`.gitignore` で外してある）。

## 1. 作業の流れ

1. **設計図（spec）を作る**（2章）：カット割り版から `specs/<id>.json` を書く。id はローマ字（例：`touma-ami`）
2. **画像を集める**（3章）：`specs/<id>.gazou.json` を書いて `scripts/gazou.py`。ログインが必要なもの（Instagram など）はMacかユーザーに頼む
3. **投稿のスクショ**（3章）：`scripts/xshot.js`
4. **素材チェック**（4章）：原寸で見る
5. **効果音**（5章）：`scripts/se_lab.py`（効果音ラボから取る。最初の1回だけ）
6. **声**（6章）：読みを確かめて `"yomi"` で直し、`scripts/koe.py`。秒数とテロップの時間が声に合う（台本の長さを測るだけなら `--dry`）
7. **書き出し・音量・サムネ**（7章）
8. **納品前チェック**（8章）：`scripts/predeliver.py` が「NG 0件」になるまで直す
9. **渡す**（9章）：完成版とサムネを送り、予約投稿をMacに引き継ぐ。台本・設計図などはコミットしてプッシュする

台本を直す必要が出たら（写真がテロップと合わない、字数が足りないなど）、台本スキルの審査をやり直してから戻る。動画の側で勝手に言葉を変えない（読みの直し `"yomi"` は画面の文字を変えないので、このスキルの中で直してよい）。

## 2. 設計図（spec）

書き方はテンプレートの README.md と `references/spec.md`。カット割り版のカットを1つずつ写す。
- テロップの文は**台本と一字一句同じ**にする（改行は `\n`）
- 冒頭画面のパターン、写真の切り取り（`focusY`）、溜めのモザイク（`single` の `mosaic`）、2枚比較の並べ方（`layout`）は、カット割り版の指示どおりにする
- 画面に出典のラベルは出さない（`creditLabels` は書かない＝出さない。2026-11-08 ユーザーが決定）。出典は概要欄に書く
- 効果音は spec に書かなくてよい（6章の koe.py が、ベンチマークと同じ置き方でテロップごとに書く）
- `dur` と `at` は仮でよい（6章の声で決まる）。写真がまだないカットは、`<id>/〇〇_kari.png` の仮の画像を置いておく

## 3. 画像とスクショ

**集め方の優先順位**（policy.md 3章）：①本人がSNSで出した写真 ②事務所・番組・出版社などの公式 ③報道写真（代わりがないときだけ）。まとめサイト・Pinterest・ファンの転載アカウントは使わない。

- **X の写真**：`specs/<id>.gazou.json` に投稿の status ID・何枚目か・画像の大きさ・切り取り範囲を書き、`python3 scripts/gazou.py <id>`。埋め込み用の公開の仕組み（cdn.syndication.twimg.com）で元の画像を取り、切り取って `public/<id>/` に置き、`画像の出どころ.json` に出どころを残す。書き方は `references/spec.md`
  - 切り取り範囲は、元の画像を開いて方眼を重ねて決める（顔の大きさを昔と今でそろえる。冒頭のモザイク用の今は、あごの下までの顔だけ）
- **投稿の画面のスクショ**：`node scripts/xshot.js <status ID> public/<id>/p〇_post.png`（Xの公式の埋め込み表示。日本時間・返信の欄は入れない。Playwright を使う）。撮れたら `画像の出どころ.json` に1件足す
- **Instagram など、ログインが必要なもの**：自動で取らない。写真番号・投稿URL・切り取り方を一覧にして、Macの担当かユーザーに保存を頼む（gazou.json の `manual` に書いておくと、gazou.py が最後に表示する）
- クラウドでは、通信が許可された先にしかつながらない。Xなら `cdn.syndication.twimg.com`・`pbs.twimg.com`・`platform.twitter.com`・`abs.twimg.com` が要る（2026-11-08 に許可済み）

## 4. 素材チェック（原寸で見る）

集めた写真は全部、原寸で開いて確かめる。
- 公開より前のカット（冒頭画面を含む）の写真に、答えが分かる名前の文字（テロップ・名札・ボード・アカウント名）が写っていないか
- 冒頭のモザイク用の今の写真は、あごの下までの顔だけか。首まわり・肩・胸元の肌が入っていないか
- 主役以外の一般の人（観客・ファン・家族）の顔が写っていたら、切り取るかぼかす
- 18歳になる前の写真か後かを、誕生日の日付まで見て判断する。未成年の頃の写真は公式写真・衣装・テレビのキャプチャだけ
- 場所が分かる背景（店名・建物・看板・窓の外）や位置情報が写っていたら切り取る（特に芸能活動をしていない人）
- 写真の中にある日付などの文字が、テロップの下からはみ出していないか（はみ出すなら切り取る）
- 昔と今が、モザイク越しでも違って見えるか。見えなければカット割り版の指示どおり冒頭画面をパターンCにする
- 写真の中身は加工しない（切り取り・明るさの軽い調整・冒頭のモザイクだけ）

`node scripts/render.mjs <id> --stills` でカットごとの静止画を書き出し、並べて見て、顔が切れていないか・テロップが顔にかかりすぎていないかを確かめる。

## 5. 効果音

ベンチマーク（こっそり速報の1位）の音を分析して、**同じ効果音を同じ置き方・同じ大きさの比で**鳴らす（`ベンチマークの音の調べ方/結果_こっそり速報1位.md`）。
- `python3 scripts/se_lab.py`：効果音ラボから4つの音を `public/se/bm/` に取ってくる（最初の1回。リポジトリには入れない。効果音ラボは再配布が禁止のため）。通信先 soundeffect-lab.info
  - T＝和太鼓でドドン（冒頭の画面）、C＝小パンチ、B＝パフ（1つおきの b のテロップ。C→B→C→C→B…の順）、D＝きらーん1（公開の上テロップと最後のカットの上テロップ）。a のテロップは鳴らさない
- 置き方と大きさは `scripts/koe.py` が声と一緒にテロップごとに書く（spec の `se`・`seVolume`、冒頭は `sfx.title`）。spec の `"seMode": "off"` で書かない
- BGMは入れない（ベンチマークもない）
- 概要欄の「▼読み上げの声・効果音」に「・効果音：効果音ラボ」（クレジットは任意だが書く）
- `scripts/se.py` の自作の音（ドン・ポン・ジャン・キラーン）は、効果音ラボにつながらないときの代わり

## 6. 声（青山龍星1人。高さ・抑揚は元のまま）

声は VOICEVOX の青山龍星（ノーマル）1人。高さ・抑揚は元のまま、速さだけベンチマーク①1位（1秒8.7音）に合わせて約29秒の長さを保つ（koe.py の DEFAULT_VOICES：番号13・speed 1.05、高い音は切らない）。
- いきさつ：ベンチマークの声を測って、2人（a＝九州そら、b＝青山龍星）がテロップごとに交互に話し、高さ・抑揚・こもり方（5.8kHzより上を切る）まで合わせた版も作った。しかし声色に違和感があるので、元の青山龍星に戻した（2026-11-08 ユーザー「声はもとの青山でいい。声色がおかしい、違和感」）。勝手に2人の声や声の加工に戻さない
- テロップは1つごとに a・b と数え、効果音の鳴らし方（1つおきのテロップ（b）＝小パンチ・パフ）にだけ使う。a と b は同じ声
- 2人の声に戻すときは、spec の一番上に `"voices": {"a": {"id": 16, "pitch": 0.101, "intonation": 0.28, "speed": 1.44}, "b": {"id": 13, "pitch": 0.061, "intonation": 0.20, "speed": 1.04}}` と `"voiceLowpass": 5800`（ユーザーが頼んだときだけ）
- 間：文と文の間0.27秒、カットの頭0.03秒、次のカットまで0.26秒、最後の声のあと1.1秒（ベンチマークどおり）。冒頭のカットも、声が終わったらすぐ次へ（字数で延ばさない）
- 反応集のずんだもんは使わない

1. VOICEVOX を用意する：クラウドでは `bash scripts/setup_voicevox.sh <置き場所>`（1回だけ。GitHub と PyPI から取る。GitHub が混んで 504 が出たら、時間をおいてもう一度）。setup_voicevox.sh は Linux 用。Macでは VOICEVOX CORE の macOS 用の wheel と ONNX Runtime で同じように組み立てる（koe.py はそのまま使える）
2. **読みを先に確かめる**：全部のテロップの読み（カタカナ）を出して、読み間違いを探す。よくある間違い：
   - 人の名前（「當真あみ」→あみだけ読む）、グループ名の数字（「欅坂46」→よんじゅうろく）、英字（「non-no」→エヌオー…）
   - 年齢の言い方（「20歳」→にじゅっさい。はたち）、連濁（「待った甲斐」→がい。かい）、数字のあとの「超え」（ちょうえ。ごえ）
   - 見つけたら spec の一番上の `"yomi"` に `"画面の文字": "読み"` で足す（画面の文字は変わらない）
3. 長さを測る：`VOICEVOX_DIR=<置き場所> <置き場所>/venv/bin/python scripts/koe.py <id> --dry`（ファイルも spec も書き換えない）。カットごとの秒数・合計・公開の秒が出る。合計は27〜31秒（ベンチマーク①1位は29.2秒）、公開は型Aで14〜15.5秒あたり。入らなければ台本スキルに戻って削る（声の速さはベンチマークに合わせてあるので変えない）
4. 声を作る：`VOICEVOX_DIR=<置き場所> <置き場所>/venv/bin/python scripts/koe.py <id>`
   - テロップを上→下の順に読んだ声を `public/<id>/voice/cutNN.wav` に作り、各カットの `dur` と下テロップの `at`（読み始める秒）、テロップごとの効果音を書き換える（元の spec は .bak に残る）
   - カット1も最後のカットも、秒数は声に合わせて自動で決まる（冒頭は声のあと0.26秒、最後は1.1秒）

クレジット：概要欄に、使った声を全部書く（「・読み上げ：VOICEVOX:青山龍星」）。koe.py が spec の `voiceCredits` に残し、predeliver.py が概要欄にあるか確かめる。どちらの声も、クレジットを書けば商用（収益化）可。

## 7. 書き出し・音量・サムネ

```
node scripts/render.mjs <id>
ffmpeg -y -i out/<id>.mp4 -c:v copy -af loudnorm=I=-19.6:TP=-2.5:LRA=4 -c:a aac -b:a 192k out/<id>_kansei.mp4
node scripts/render.mjs <id> --stills && cp out/still/<id>_カット01.png out/<id>_thumbnail.png
```
- 背景の放射線は自動で左回りに回る。冒頭画面の写真は少しずつ大きくなる
- 書き出したら、数か所のコマを抜き出して見る（モザイク→公開の切り替え、下テロップの積み方、2枚比較）。`ffmpeg -ss <秒> -i out/<id>_kansei.mp4 -frames:v 1 コマ.png`

## 8. 納品前チェック

```
python3 scripts/predeliver.py <id> ../〇〇_台本.txt ../〇〇_台本_編集カット割り.txt
```
見ること：素材と声がそろっている（仮の画像が残っていない）／合計27〜31秒・7カット・テロップ14個・公開の位置／テロップの字数と行（1行11字、タイトル枠は10字）／声より短いカットがない／台本2ファイルと設計図のテロップが一字一句同じ／概要欄に画像の出どころの全URL・使った声（「VOICEVOX:青山龍星」）・効果音のクレジットがあり、メモが残っていない／完成版が素材より新しい。

「NG 0件」になるまで直す。「注意」は目で確かめる。

## 9. 渡す・予約投稿の引き継ぎ

1. 完成版の動画とサムネをユーザーに送る（ファイルを送る機能があれば使う）。伝えること：長さ・公開の位置・直した読み・効果音・チェックの結果・まだのこと
2. 台本・設計図・gazou.json・スクリプトの変更をコミットしてプッシュする（写真・声・完成版は入らない）
3. **予約投稿はユーザーの承認をもらってから**、Macで Chrome から YouTube Studio に入れる（クラウドからはログインできない）。引き継ぐこと：
   - チャンネル：答え合わせ速報（旧ゴッドブックス）。反応集のチャンネルと取り違えないよう、毎回チャンネル名を確かめる
   - タイトル・説明欄（プレーン版の【概要欄】）・タグ・ハッシュタグ・サムネ・「子ども向けではない」
   - 投稿時刻：毎日2本、18:00と21:00（日本時間）。空いている枠に順に入れる
   - プレーン版の【要確認】にある、公開後にすること（コメントを保留にする、コメント欄が使えるかを確かめる、など）
4. 投稿したら、台本メモ.txt のその回の行に、投稿日時を書き足す（再生数はあとで）
