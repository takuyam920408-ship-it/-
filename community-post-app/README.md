# コミュニティ投稿アシスタント

URL を1本貼るだけで、**画像収集 → 投稿画像の加工 → 投稿文の生成** までを自動でやる
ローカル Web アプリ。最後の「Studio に貼って投稿/予約」だけ人間がやる半自動ツール。

**AI（LLM）は一切使っていません。** 使っているのは辞書マッチ・正規表現・テンプレート差し込み・
ルールベースのスコアリングだけなので、API 費用ゼロ・出力のブレなし・オフラインでも動きます。

---

## なぜ「半自動」なのか

YouTube Data API v3 には**コミュニティ投稿を作成するエンドポイントが存在しません**。
公式 API で投稿できない以上、「ボタン1つで投稿完了」は規約を守る限り作れません。

一方、YouTube Studio 側にはコミュニティ投稿の**予約機能**があります。
そこでこのアプリは「投稿ボタンを押す直前まで」を全部やります。
週1回まとめて生成 → Studio で貼り付けて予約、で1週間分が片付きます。

> Playwright 等で Studio を自動操作すれば完全自動化は技術的に可能ですが、
> 公式 API 以外の自動アクセスは YouTube 利用規約違反です。このアプリはやりません。

### 方法A：ターミナルにコピペ（一番確実・おすすめ）

「ターミナル」を開いて、下の1行をまるごとコピーして貼り付け、Enter を押すだけです。
（Launchpad → その他 → ターミナル、または command + space で「ターミナル」と検索）

```bash
cd ~/Desktop && git clone -b claude/affectionate-sagan-ur4bk7 https://github.com/takuyam920408-ship-it/-.git community-post && cd community-post/community-post-app && ./start-mac.command
```

**`start-mac.command` をダブルクリック**するだけです。

### フォント（けいふぉんと）

画像に焼き込む文字は **けいふぉんと** を使います。ライセンスの都合ではなく
配布元からの自動取得ができなかったため、**フォント本体はリポジトリに含めていません**。
各自で入れてください（Apache License 2.0・商用利用可）。

1. https://font.sumomo.ne.jp/font_1.html から zip をダウンロード
2. 解凍して出てくる `keifont.ttf` を **`assets/fonts/` に置く**
3. 画面を再読み込み（サーバーの再起動は不要）

Mac なら `keifont.ttf` をダブルクリックして Font Book で入れてもかまいません
（`~/Library/Fonts/` に入るので、そちらも自動で探します）。

けいふぉんと以外で描画されているときは、**画面上部に警告が出ます**。
起動時にも黒い窓に「けいふぉんとを使います」か、見つからない旨が表示されます。

探す順番:

1. 環境変数 `CPA_FONT` で指定したフォント
2. `assets/fonts/keifont.ttf`（ファイル名に `kei` を含む .ttf/.otf/.ttc でも可）
3. `~/Library/Fonts/keifont.ttf` / `/Library/Fonts/` / Windows のフォントフォルダ
4. `assets/fonts/` にある任意の日本語フォント
5. OS 標準の日本語フォント（ヒラギノ、メイリオ、IPA ゴシック）


## 使い方（画面の1〜7）

1. **URL を取り込む** — アニメ公式サイト / ニュース記事の URL を貼る。自分の動画 URL は任意（`{動画URL}` に入る）。
   ページから画像が取れない場合は、同じ画面の「ページから画像が取れないとき」を開いて
   **画像ファイルを読み込む**か**画像URLを直接貼る**（後述）
2. **画像を選ぶ** — スコア順に並んだ候補から1枚クリック。ロゴ・アイコン・広告バナー・小さすぎる画像は自動で除外済み
3. **抽出結果を確認・修正** — 作品名 / 話数 / キャラ名
4. **トリミング＆露出を黒モザイク（必須）** — 「トリミングして検出」を押すと、切り抜いた絵の上に
   露出（肌色）の候補枠が出る。**ドラッグで追加 / 枠をクリックで削除**して仕上げる
5. **黒帯の解説文（必須）** — 画像の下に入る黒帯の文。**空だと生成できません**
6. **投稿文を生成** — テンプレートから3案。気に入った案をコピー
7. **投稿して記録** — Studio で貼り付け・予約したあと「投稿済みとして記録」

## ページから画像が取れないとき（画面1）

このアプリは HTML を読むだけなので、次のようなページからは画像を取れません。

- **JavaScript で画像を描画するサイト**（HTML に `<img>` が無い）
- **年齢確認などのゲート**があるサイト（受け取るのはゲートの HTML だけ）
- **ホットリンク防止**で外部からの画像取得を拒否しているサイト
- 保護されたビューアーで配信しているサイト（分割・難読化されており、仕様上取得できない）

採用0枚になった場合は、画面がその内訳（`HTML から N 枚見つかり、M 枚ダウンロード成功`）と
原因の切り分けを出します。そのうえで、次の2つの入口が使えます。

| 入口 | 使う場面 |
|---|---|
| **画像ファイルを読み込む** | 画像を手元に保存済みのとき。一番確実 |
| **画像URLを直接貼る** | 画像を右クリック →「イメージのアドレスをコピー」できたとき |

どちらの場合も、以降のトリミング・黒モザイク・黒帯・文面生成はそのまま使えます。
作品名や話数は自動抽出できないので、画面3で手入力してください。

## DMM アフィリエイト API から取り込む（画面1）

スクレイピングではなく**公式 API**（DMM Web サービス）を使います。年齢認証ゲートも
ページ解析も関係なく、商品情報と一緒にサンプル画像の URL が正式に取得できます。

### 準備

1. [DMMアフィリエイト](https://affiliate.dmm.com/api/) で **API ID** と
   **アフィリエイト ID** を取得（アフィリエイト ID は末尾が 990〜999 のもの）
2. 画面1の「DMM アフィリエイト API から取り込む」を開いて2つを入力・保存

保存先は `data/dmm_api.json`（パーミッション 600、`.gitignore` 済み）。
環境変数 `DMM_API_ID` / `DMM_AFFILIATE_ID` でも指定でき、そちらが優先されます。

### 使い方

- **キーワード**か**商品ID（cid）**のどちらかを入れて検索
- `service` / `floor` は任意。分からなければ **「floor 一覧」**ボタンで一覧を取得できる
- 結果の**サムネイルをクリック**すると、その画像が取り込まれ、
  以降のトリミング・黒モザイク・黒帯・文面生成にそのまま流れる

### 項目名がズレていたら

このクライアントは公開仕様にもとづいて書いていますが、実際の応答と食い違う
可能性があります。そのため検索結果の下に **「生のJSON（1件目）を見る」** を付けてあります。
取得できていない項目があれば、そこで実際のキー名を確認して
`app/adapters/dmm_api.py` の `_item_to_dict()` を直してください。

値の取り出しは大文字小文字の揺れ（`URL` / `url`）、配列と単体 dict の揺れ、
`sampleImageURL` の形の違いに耐えるようにしてあります。
`tests/test_dmm_parse.py` で両方のパターンを検証できます。

```bash
python3 tests/test_dmm_parse.py
```

### 出口についての注意

このアプリはもともと YouTube コミュニティ投稿用です。**成人向け作品のサンプル画像は、
黒モザイクをかけても YouTube には投稿できません**（加工の有無は判断材料になりません）。
アフィリエイトのブログ・サイト用に画像を用意する、といった用途で使ってください。

## 露出の黒モザイクについて（画面4）

### 何をしているか

YCbCr 色空間のしきい値処理という古典的な画像処理で「肌色のかたまり」を探し、
粗いグリッドに落としてから連結成分を矩形に束ねます。AI も学習モデルも使いません。
枠は検出結果より **12% 外側に広げて**あります（検閲用途なので「隠しすぎ」に倒す方針）。

### 必ず目で確認してください

自動検出で分かるのは「肌色かどうか」だけです。つまり:

- **顔も肌色なので顔も検出されます**（消したければ枠をクリック）
- **影が濃い・色味が特殊な絵は見落とします**（ドラッグで追加）
- 服や背景が肌色に近いと誤検出します

**自動検出は候補出しであって、最終判断ではありません。** 必ずプレビューを見て、
足りない部分をドラッグで足してから生成してください。

### 隠し方の3モード

| モード | 見え方 | 用途 |
|---|---|---|
| **黒ベタ塗り**（既定） | 完全に黒で塗りつぶす | 一番確実。迷ったらこれ |
| 黒モザイク | モザイク化して 55% 黒に沈める | 形をうっすら残したいとき |
| ぼかし | ガウスぼかし | やわらかく隠したいとき |

調整したいときは `app/censor.py` の定数を変えてください。

| 定数 | 既定 | 意味 |
|---|---|---|
| `CB_MIN/MAX`, `CR_MIN/MAX` | 77–135 / 133–180 | 肌色とみなす色の範囲。広げると拾いやすく、誤検出も増える |
| `GRID` | 40 | 判定の細かさ。上げると小さい領域も拾う |
| `CELL_SKIN_RATIO` | 0.6 | セル内の肌色率のしきい値。下げると拾いやすくなる |
| `MIN_CELLS` | 6 | これ未満の小さな塊は無視 |
| `PAD_RATIO` | 0.12 | 枠を外側に広げる割合 |

## 黒帯の解説文は必須・最大2行（画面5）

画像の下には必ず黒帯（不透明の黒）＋解説文が入ります。空のまま生成しようとすると
`黒帯に入れる解説文は必須です。` というエラーになり、画像は作られません。

**文字は2行までです。** 2行に収まらないときの挙動:

1. まず**フォントを段階的に縮めて**2行に収めようとする（基準サイズの 55% まで）
2. それでも収まらなければ、**末尾を「…」で切る**

入力中に「`35 文字・2 行（収めるため文字を少し小さくします）`」のように
実際の描画と同じ計算で測った結果が出ます。切られる場合は黄色で警告します。
生成後も、切り詰めが起きたらプレビューの上に警告が出ます。

行数を変えたいときは `app/compose.py` の `MAX_CAPTION_LINES` を変更してください。

## 重要な制約：AI なしでは「画像の中身」は読めません

「画像に合った投稿文」を機械が作るには、画像を見て理解する必要があります。AI なしでは不可能です。

代わりにこのアプリは、**画像と一緒に付いてきたテキスト**から文面を組み立てます:

- `alt` 属性 / `<figcaption>` / 画像直前の見出し
- ページの `<title>` `og:title` `og:description`
- URL のパス（`/anime/yanineko/12/` → 作品=ヤニねこ、話数=12）

実用上はこれでほぼ足りますが、**画像とテキストがズレることはあります**。
だから画面3でプレビュー確認を1ステップ挟んでいます。ここは省略しないでください。

埋まらなかったスロットは空のままにし、そのスロットを `requires` に持つテンプレートは
候補から外れます（**埋まっていない値を推測で書かない**設計）。

## カスタマイズ

育てる価値があるのはこの2ファイルだけです。編集後は画面をリロードするか
`POST /api/reload` で再読み込み（サーバー再起動は不要）。

### `data/dictionary.yaml` — 作品辞書

```yaml
works:
  - id: yanineko          # 履歴DB上のキー
    name: ヤニねこ         # {作品名}
    tag: ヤニねこ          # {作品名タグ}（# は書かない）
    aliases: [ヤニ猫, yanineko]   # 表記ゆれ。マッチ判定に使う
    characters: [ヤニねこ, シャブねこ]  # {キャラ名}
    phrases:              # {感想フレーズ}（この作品専用）
      - "今回も情緒ぐちゃぐちゃにされた…"
generic_phrases:          # 作品が特定できなかったとき用
  - "コメント欄の温度が高い回でした"
```

**ここを増やすほど抽出精度と文面の質が上がります。** 最初の投資先はここ。

### `data/templates.yaml` — 投稿文テンプレート

```yaml
templates:
  - id: shinsaku_kokuchi
    type: 新作告知
    requires: [作品名, 話数]   # 全部埋まっていないとこのテンプレは使われない
    weight: 3                 # 抽選の重み。伸びたテンプレの数値を上げる
    text: |
      【{作品名}】{話数}話の反応まとめました！
      {感想フレーズ}
      ▶ {動画URL}
      #{作品名タグ} #反応集
```

使えるスロット: `{作品名}` `{作品名タグ}` `{話数}` `{キャラ名}` `{タイトル}`
`{元記事URL}` `{動画URL}` `{サイト名}` `{感想フレーズ}`

## 画像スコアリングのルール（`app/scoring.py`）

| 加点 | | 除外 | |
|---|---|---|---|
| `og:image` | +50 | URL に `logo` `icon` `banner` `ad` など | 即除外 |
| `twitter:image` | +40 | 短辺 200px 未満 | 即除外 |
| 解像度（面積） | 最大 +40 | 縦横比 3:1 超（バナー形状） | 即除外 |
| 作品名が alt / URL に一致 | +20 | | |
| `main` `key` `visual` `kv_` などのファイル名 | +12 | | |
| 投稿向きの縦横比（1:1〜1.9:1） | +10 | | |
| キャプションあり / alt あり | +8 / +5 | | |

誤爆したら `EXCLUDE_PATTERNS` / `BOOST_PATTERNS` を足してください。

## 履歴とネタ被り防止（`data/history.db`）

「投稿済みとして記録」を押すと SQLite に保存され、次から効きます:

- 同じ元記事 URL を90日以内に使っていたら**警告**を出す
- 使用済みの画像には候補一覧で「使用済み」バッジ
- 直近8件で使ったテンプレは抽選の重みを 1/5 に下げる
- 同じ作品で直近10件に使った `{感想フレーズ}` は選ばない

## 著作権について

他サイトから収集した画像をそのまま投稿に使うのは、公式配布素材・プレスキット以外は
リスクがあります。このアプリは画像を**集めて見せるところまで**しかやりません。
使ってよい画像かの判断は利用者の責任です。

安全側に倒すなら、画像源を自分の動画のサムネ/フレームにするのが確実です。
その場合は `app/adapters/` に YouTube 用アダプタを足して `ADAPTERS` に登録すれば、
残りの処理（スコアリング・加工・文面生成・履歴）はそのまま使えます。

なお取得時は **robots.txt を尊重**します。拒否されているサイトはエラーになります
（どうしても必要なときだけ `CPA_IGNORE_ROBOTS=1`。判断は自己責任で）。


| `CPA_FONT` | 自動検出 | 使うフォントのパス。けいふぉんとより優先される |
| `CPA_HTTP_TIMEOUT` | `15` | 取得タイムアウト（秒） |
| `CPA_MAX_IMAGE_PROBES` | `24` | 実寸を測る画像の上限枚数 |
| `CPA_IGNORE_ROBOTS` | `0` | `1` で robots.txt を無視 |
| `CPA_USER_AGENT` | 専用 UA | 送信する User-Agent |
| `DMM_API_ID` | なし | DMM アフィリエイト API の API ID |
| `DMM_AFFILIATE_ID` | なし | 同 アフィリエイト ID（末尾 990〜999） |
